Output: /home/claude/astro/books/<BKnn>/rules.jsonl (create dir files yourself), one JSON object per line, schema:
{"id":"<BKnn>_0001","system":"lalkitab|parashari|jaimini|kp|tajaka|other","engine_role":"rule|remedy|nishani|donot|do|timing|yoga|foundation","life_area":"career|wealth|marriage|children|health|status|setback|foreign|property|education|character|longevity|general","input":"precise chart condition, e.g. 'Saturn in 10th house with Sun in 4th'","outcome":"what happens / the sign (nishani) / the advice","timing":"natal|dasha|transit|age N|annual|...","strength_note":"conditions, exceptions","remedy":"remedy text if the rule gives one (else empty)","source":"URL or book + chapter/page","quote_short":"","confidence":"book-claim|teacher-claim|web-claim"}

Put text slices into document.body.innerText and read via get_page_text (javascript_tool output is capped ~1 KB). Read in slices of ~60-100k chars. astro.com style rate-limits exist: go slowly, no bursts.
- Skip content with no checkable astrological content. Do not stop at a target count: cover the source fully; if you run out of room, report exact offsets/URLs reached.
- Final report (short): sources covered with sizes/offsets, rule counts by engine_role, what was unreachable and why.
